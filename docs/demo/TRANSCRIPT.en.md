# Narration transcript

## Does the source support this code?

When you see a proposed code, the first question is simple: does the source really support it?

Click the page number to find the passage on the right. Let’s walk through the review from here.

## Three places to look

Start with three areas. Choose a report on the left.

Check the coding in the middle, with the original text alongside it.

## Choose what to review next

Use the list at the top left. All pilot reports shows the whole set.

To pick up where you left off, choose Verification pending.

You can also focus on included or excluded reports.

## An exclusion still needs evidence

This report is marked Excluded, so further extraction stops here.

The reason and its evidence remain available. You can still check the passage in context.

## Confirm it, or explain the change

After checking the evidence, choose Correct if this item is right.

If something needs changing, choose Revise.

A note box opens below. Explain what is wrong and how you think it should change.

## Feedback complete; decisions still open

Once every item has feedback, the report moves to Verification complete.

But look: one revision is still recorded. The team needs to resolve it.

## Four stages for included reports

Now open an included report. These four tabs organize the work.

In Screening, expand Foundational conditions and check each requirement.

## Follow the rule back to its evidence

Each judgment includes a reason and a source you can inspect.

Next, look at Construct pathways. These conditions come from the team’s codebook.

## How was this review conducted?

Review profile brings together the question, scope, and methods of this review.

Start with that overview, then check the individual items below.

## Does the concept mapping fit?

In Concepts, compare the source’s definitions with the team’s descriptive coding.

Deciding whether that mapping makes sense is a human judgment.

## What does this review conclude?

This stage captures the claims and conditions reported by this particular review.

Check the level of evidence behind each claim. This is not a completed synthesis across reviews.

## From a page number to the sentence

For this example, click PDF page eighteen to find the cited sentence.

Yellow helps you locate it. Read the context before deciding whether the code is supported.

## Need more room for the PDF?

If the PDF feels cramped, drag the divider to the left.

The source now has more space.

## Zoom in, then keep reading

For small text, use the zoom control at the top right.

At one hundred and fifty percent, both the text and its highlight become larger.

Scroll inside the PDF to read more context. The coding panel stays in place.

## Turn the page, then return your feedback

Use the arrow to turn the page. The previous highlight clears.

When you finish this round, export your feedback and return it to the team.

## AI prepares; people make the judgments

Develop the rules on a sample first. Then AI can prepare the next batch for people to verify.

The aim is to make evidence easier to find and compare, so people can make informed judgments.
